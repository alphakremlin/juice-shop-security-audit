Critical Security Findings
Finding #1 — SQL Injection on Search Endpoint
Critical
EndpointGET /rest/products/search?q=apple'
OWASPA03:2021 — Injection
DetailQuery parameter concatenated directly into SQLite query. Single quote breaks the query. Full database readable via ' OR 1=1--. UNION-based data exfiltration possible.
FixUse parameterised queries / prepared statements. Never concatenate user input into SQL strings.
Finding #2 — Authentication Bypass via SQL Injection
Critical
EndpointPOST /rest/user/login with {"email":"' OR 1=1--"}
OWASPA07:2021 — Identification and Authentication Failures
DetailClassic OR 1=1 comment bypass authenticates as admin without knowing any credentials. Returns valid JWT token for the admin account.
FixParameterise the login query. Implement account lockout after 5 failed attempts. Add MFA for admin accounts.
Finding #3 — Broken Access Control (IDOR)
Critical
EndpointPUT /api/Users/:id
OWASPA01:2021 — Broken Access Control
DetailAuthenticated users can modify any other user's profile by changing the :id in the URL. Server verifies JWT presence but not JWT ownership vs resource owner.
FixEnforce server-side ownership check. JWT subject must match resource owner ID on every write operation.
Finding #4 — Stored XSS in Product Content
Critical
EndpointPOST /rest/products/:id/reviews
OWASPA03:2021 — Injection (XSS)
DetailReview text accepts and renders raw HTML. Payload <iframe src="javascript:alert('XSS')"> executes in all users' browsers who view the product.
FixSanitise all user-supplied HTML server-side with DOMPurify or equivalent. Never render raw user input as HTML.

High Severity Findings
Finding #5 — Weak JWT Signing
High
OWASPA02:2021 — Cryptographic Failures
DetailJWTs signed with a weak secret or "none" algorithm in some versions, allowing token forgery. JWT payload is base64-encoded but NOT encrypted — email, ID, and role visible to anyone who intercepts the token.
FixUse RS256 asymmetric JWT signing. Enforce minimum secret length. Explicitly reject "none" algorithm.
Finding #6 — Stack Traces Returned in Error Responses
High
DetailUnhandled server errors return full Node.js stack traces in the HTTP response body. Attackers can read file paths, function names, and framework versions.
FixReturn generic error messages to clients. Log full stack traces server-side only.
Finding #7 — All Security Headers Missing
High
MissingContent-Security-Policy, X-Frame-Options, X-Content-Type-Options, Strict-Transport-Security, Permissions-Policy
OWASPA05:2021 — Security Misconfiguration
FixAdd helmet.js middleware to Node.js/Express. Sets all standard security headers automatically.
